# WordBase

一个给**自己用**的、长期常驻后台的生词本。不限于英语：一个词条可以同时挂多个读音（日语同形异读很常见），
也可以是一条语法点。复习节奏用 FSRS（遗忘曲线）排程，到点用 Windows 通知在后台向你提问。

> 设计取向：**数据完全属于你**。便携模式运行、SQLite 单文件、不联网也能用；只有你自己点了「用大模型填充」才会发一次请求。

---

## 它解决什么问题

你读书、听播客时遇到不认识的词 → 查完顺手扔进 WordBase → 之后它按遗忘曲线在后台提醒你复习：

```
到点 → Windows 通知「认识 / 不认识」
 ├─ 不认识 → 展开释义与例句 → 你自评（忘记/模糊/记得/很轻松）
 └─ 认识   → 按概率（默认 25%）抽一道四选一
              ├─ 答对 → 记为「确实记得」
              └─ 答错 → 记为「有印象但记混了」，并记录混淆对，日后更容易再撞见
```

同一个词被反复录入/查到不会被拒，而是记一次「遇见」并把它的复习时间往前挪一点。

## 主要功能

| 模块 | 说明 |
|---|---|
| 录入/查词 | 先查重：已存在就提示并展示原有内容；不存在才进入录入 |
| 三条录入路径 | ① 大模型直接填充 ② 复制提示词去网页版，再把回复粘回来 ③ 纯手填 |
| 统一的确认表单 | 三条路径最终都落到同一个可编辑表单，**你确认后才会入库** |
| 词条结构 | 词条 + 多个读音（标记常用/少见）+ 归属到读音的释义 + 带词性的例句 |
| 例句质量门槛 | 目标：每个「读音 × 词性」≥ 2 条例句。凑不满时模型必须写明原因；手动录入不足只警告 |
| 补齐例句 | 例句不足时点「让模型补齐例句」，只补缺口，不会重排你已核对过的内容 |
| 未校对标记 | 大模型产出的一切默认「未校对」，复习时会提示你还没核对过 |
| 词库 | 按词形/读音/释义搜索，按语言筛选，随时编辑或删除 |
| 复习 | FSRS 调度、四档自评、选择题抽测、每日上限、提醒节奏与时间窗 |
| 通知 | 原生 Windows Toast（带按钮）+ 自绘卡片兜底；带**可感知**的系统拦截检测与自检向导 |
| 常驻 | 托盘图标 + 右键菜单，关窗收进托盘，可选开机自启 |
| 便携 | 数据放在程序目录 `data\` 下，整个文件夹拷走就能用；一键导出/导入备份 |

## 系统要求

- Windows 10 1809 或更高（Windows 11 体验最佳）
- **便携版**：无需安装任何东西
- **小体积版**：需要 .NET 9 桌面运行时 与 Windows App Runtime 1.8

## 开始使用

### 1. 运行

从发布包里选一个：

- `WordBase-portable\WordBase.exe` —— 自包含，双击即用（约 200–260 MB）
- `WordBase-framework\WordBase.exe` —— 约 40 MB，但依赖已安装的运行时

首次启动会在 exe 同级创建 `data\` 目录，里面是：

```
data\
  wordbase.db      # 词库与复习记录（SQLite）
  secrets.json     # DPAPI 加密后的 API Key
  backups\         # 导出的备份
  logs\            # 运行日志（排查问题用）
```

### 2. 加第一个词

1. 顶部选语言（英语 / 日语 / …）和类型（单词 / 语法）
2. 输入词条，点「查询」
3. 没查到 → 进入录入：
   - **用大模型填充**：先在设置里配好接口，点一下即可
   - **复制提示词**：把提示词粘到任意网页版大模型，再把整段回复粘回「粘贴大模型回复」框，点解析
   - **手动录入**：直接填读音、释义、例句
4. 检查黄色警告（例句不足之类）→ 点「保存词条」
5. 如果例句不够，点「让模型补齐例句」——只补缺的那几格，不会重排你已经看过的内容

### 3. 读音与例句的处理策略

这两处刻意「宁缺毋滥」，因为多给等于增加你的记忆负担：

- **读音只给常用的**。绝大多数词只有一个常用读音，那就只有一条。提示词明确禁止列罕见读音、方言读音、
  古语读音、专有名词专用读音。只有当某个非主流读音对中文母语学习者有真实价值（常见材料里会遇到、
  或与常用读音构成高频易混对比）时，才允许额外给一条，并标注为非主流、写明理由。
- **例句凑不满就说清楚**。每个「读音 × 词性」目标是 2 条；如果某格确实写不出第二条自然例句，
  模型只给 1 条并在备注里说明原因（界面上直接可见）。提示词明确禁止编造、禁止把同一句改几个词充数。
- 你随时可以手动改任何一格；手动录入不足只警告、不阻止保存。

### 4. 配大模型（可选）

设置 → 大模型，填三项即可，走 OpenAI 兼容的 `/chat/completions`：

| 服务 | BaseUrl | 模型示例 |
|---|---|---|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` |
| Ollama（本地） | `http://localhost:11434/v1` | `qwen2.5:7b` |
| LM Studio（本地） | `http://localhost:1234/v1` | 任意已加载模型 |

> API Key 用 Windows DPAPI 加密，**绑定当前 Windows 用户**。换机器或换用户后解不开，需要重新填——这是刻意的：
> 备份文件泄漏也拿不到明文。公用电脑可以关掉「保存密钥」。

### 5. 让它常驻

- 关窗只是收进托盘，提醒照常工作
- 右键托盘图标：打开 / 开始复习 / 暂停提醒 / 设置 / 退出
- Windows 11 默认把新应用的托盘图标收进「隐藏的图标」溢出区，想常驻显示请在任务栏设置里把它设为「显示」
- 设置里可开「开机自启」（写入 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`，不需要管理员权限）
- 便携模式把程序放进 U 盘时，自启会自动关闭（拔盘开机只会弹错误框），并会在每次启动时自动修正注册表里的路径漂移

## 通知为什么有时不出现

Windows 有三层东西会静默吞掉通知，WordBase 对它们做了**可感知**处理：

| 情况 | 能否自动识别 | 处理 |
|---|---|---|
| 系统设置里本应用通知被关 | ✅ 确定 | 检测到后直接改走自绘卡片，不假装发送成功 |
| 组策略关闭通知 | ✅ 确定 | 同上，并在设置页说明原因 |
| 专注助手 / 勿扰 / 全屏演示 | ✅ 确定 | 同上 |
| 通知发了但你没看见 | ❌ 系统不提供回执 | 记录「无响应」计数，设置页会给出改通道的建议（不擅自改） |

**自检向导**：设置 → 通知 → 「发送测试通知并自检」。会显示 AUMID 注册状态、系统开关、当前通知状态，
并真的发一条带按钮的测试通知，要求你 15 秒内点一下确认——点到了才算「可达」。

通知通道三选一：**自动**（原生优先，检测到被拦截就改自绘卡片，推荐）/ **仅原生** / **仅自绘卡片**。

## 复习算法

用 **FSRS-5**（比 SM-2 更准，只有 19 个参数，无训练也能直接跑），并把你设计的「认识/不认识」交互映射成置信度：

| 你的操作 | 置信度 | FSRS 评分 | 说明 |
|---|---|---|---|
| 认识 + 选择题答对 | 1.0 | Good | 强证据 |
| 认识 + 没被抽中 | 0.7 | Hard | 有印象，小幅延长 |
| 认识 + 选择题答错 | 0.2 | Again（降幅封顶） | 大概率是记混了，同时记录混淆对 |
| 主动点「不认识」 | 0.1 | Again | 进入 10 分钟后的重学 |
| 你自己额外点「很轻松」 | — | Easy | 只有主动选择才会用 Easy |

- 遗忘造成的稳定度下降有**下限保护**（不低于原值 × 0.25），避免一次手滑把间隔打回一天
- 每次作答的原始置信度都写进 `review_log.confidence`，将来要换成「软标签」算法也不用迁移数据
- 目标保持率默认 90%（可调），决定间隔的长短

## 便携与备份

- 数据在程序目录 `data\` 下；目录不可写（例如放进 Program Files）会自动回退到 `%LOCALAPPDATA%\WordBase` 并在设置页说明
- 设置 → 系统与数据：`打开数据目录` / `导出备份`（zip）/ `导入备份`（导入前自动再备份一份当前数据）
- 备份包里含加密后的密钥，**只能在本机本用户下解开**

## 从源码构建

```powershell
# 依赖：.NET 9 SDK
dotnet build WordBase.sln -p:Platform=x64

# 跑测试（纯逻辑 + SQLite 集成测试，不需要 GUI）
dotnet test tests\WordBase.Core.Tests\WordBase.Core.Tests.csproj

# 开发时直接运行
dotnet run --project src\WordBase.App\WordBase.App.csproj -p:Platform=x64

# 出发布包（两种形态）
powershell -ExecutionPolicy Bypass -File scripts\publish.ps1
```

### 项目结构

```
src/
  WordBase.Core/     领域模型、词形规范化、例句校验、FSRS 调度、置信度映射、用例服务（无 UI / 无 IO）
  WordBase.Data/     SQLite schema 与迁移、仓储、设置、DPAPI 密钥存储
  WordBase.Llm/      OpenAI 兼容客户端、提示词模板、补例句二次请求、容错 JSON 解析
  WordBase.App/      WinUI 3 界面、托盘、通知、调度器、备份
tests/
  WordBase.Core.Tests/  64 个单测与集成测试
docs/
  logo.png           应用图标（源文件在 Assets/app.ico，多尺寸）
```

技术选型说明：WinUI 3（Windows App SDK）+ .NET 9，未打包（unpackaged）运行，天然支持便携。
托盘图标直接调 Win32 `Shell_NotifyIcon`，通知走 `AppNotificationManager`，不依赖第三方 UI 控件。

## 已知限制 / 后续计划

- **批量导入**（CSV / JSON / Anki apkg）尚未实现，schema 与解析器已预留
- 目前是 Windows 专用。若将来要跨平台，业务层（Core/Data/Llm）可原样复用，只需重写界面层
- 同形异读会合并成**一个词条下的多个读音**；若你想把「生（せい）」和「生（なま）」彻底当成两条记录，需要改查重键
- 例句不做语法正确性自动校验（大模型会幻觉），所以保留了「未校对」标记，请自己过一眼
